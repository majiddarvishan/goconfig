# goconfig v1.7.0 — Release candidate notes

**Status:** DRAFT — not a published release until the `v1.7.0` tag exists in GitHub.

## Added

- `Manager.OnReplaceCommitted(node, handler)` provides an additive notification
  API for post-persistence replacement observers.
- Multiple observers for a node are invoked in registration order after a
  successful `Manager.Replace` or `Manager.Batch`.
- A `Batch` with multiple replacements for the same path notifies each
  subscribed observer once with the final committed value.
- Invalid changes, failed persistence and dry runs send no post-commit
  notifications.

## Compatibility and limitations

- The existing `OnReplace` callback API is unchanged: it selects only the
  first registered pre-commit handler for a path and executes before persistence.
- `OnReplaceCommitted` observers do not validate or reject changes. Use an
  existing pre-commit validator with no externally visible side effects.
- Observer registrations remain until their `Manager` is discarded. There is
  no unsubscribe API. Observers must not modify the same path from their
  callback because the per-path mutation lock is still held.
- Existing package/module path and `go.mod` requirements are unchanged.

The release candidate needs a successful `Go CI` run **on the exact main
commit to be tagged** after the release-readiness PR is merged:

- `go mod tidy` leaves `go.mod` and `go.sum` unchanged.
- `gofmt` checks pass.
- `go vet ./...` passes.
- `go test -race -count=1 ./...` passes.
- `go build ./...` passes.
